# GitHub releases implementation plan

Goal: test every main push and publish signed, notarized Apple Silicon Eveil releases on version tags. User approved this design on 2026-11-06.

Architecture: GitHub-hosted macOS jobs, read-only CI, separate release job with contents write permission. Preserve the application's signing team and authenticated service identity.

- [ ] Add main/PR CI running the Swift suite and release compilation without signing secrets.
- [ ] Add v* release workflow: validate tag against Info.plist and main ancestry, run tests, import a temporary signing identity, build, notarize, staple, verify and publish a ZIP with checksums.
- [ ] Document required encrypted repository secrets; never export local credentials automatically. Validate workflows with actionlint, run tests, push main and verify GitHub CI.

Failure checks: mismatched tag, off-main tag, missing secrets, failed Apple validation and interrupted jobs must not publish a usable release. Temporary credentials must be removed on success or failure. Published releases are immutable; existing tags/releases are never overwritten.
